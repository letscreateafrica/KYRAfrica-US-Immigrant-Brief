# KnowYourRights Africa publishing workflow

The historical U.S. Immigrant Brief tracker instructions are retained in `TRACKER-EDITORIAL-INSTRUCTIONS.md`. Use them as the daily research brief when the original tracker is inaccessible; the supplied shared-chat URL is a retrospective snapshot, not a live feed. Import new tracker material only with an actual dated source record, and verify primary evidence before promoting any claim to a current newsletter, full edition or policy alert. Keep unverified historical generated text in `/tracker/`, clearly marked as such. Do not treat an old tracker headline or an embedded editorial image as new evidence.

Organize every daily issue around the three public sections: **01 / U.S. Immigrant Brief — Navigate with clarity** (immigration processes, rights, courts and official resources, with jurisdiction and dates); **02 / African Diaspora Brief — Keep your connections** (developments across Africa and U.S. communities, with transparent coverage and research limits); and **03 / Policy Alerts — See what changed** (verified notices, effective dates, source evidence and a clear distinction between proposals and rules). A section with no qualifying verified item must say so without implying that all jurisdictions were checked. Every section and item must serve African diaspora readers in the U.S.

Use the existing public Site identity in .openai/hosting.json. Restore its current pushed source through the Sites workflow before changing anything. Preserve all dated URLs and legacy files. Never run legacy-build.mjs: it replaces the unified homepage.

Publish one unified edition every two days at 6 AM America/Los_Angeles, anchored to 9 October 2026. Research and publish a dated visual newsletter daily, including intervening days. Every news item must have a concrete, explained connection to African diaspora communities living in the United States. Include verified developments from African, U.S. or worldwide channels only when the underlying primary evidence has been checked. A secondary report can add context but never replace the primary source for a policy claim. General reference links, background context, and previously reported developments must not appear as new daily news. State the event/source date and source-edition date, affected people, jurisdiction, effective date, uncertainty and reviewer attribution. If no relevant verified development is found among checked sources, publish an honest no-update note with the checked-source scope; never recycle old material as fresh. Add each reviewed issue to content.json's newsletters array, newest first, with date, editionId, title, summary and scope. The newsletter builder creates a dated URL and updates the homepage link. Check all 54 African countries, 50 U.S. states, DC and federal sources where feasible, and record actual checks in a dated coverage record; distinguish checked with no verified update from not checked. Never imply exhaustive coverage when sources were unavailable.

Edit content.json. Keep editions newest first. Each new edition uses a unique YYYY-MM-DD id/date, title, type, summary and items. Each item needs topic, place, title, text, status and sources with title, HTTPS url and checked date. Historical legacy entries use path to their preserved page. Include what changed, affected people, dates, relevance and uncertainty in item text. Preserve old editions; document corrections explicitly with dates.

Policy alerts additionally require unique id, jurisdiction, status (In effect, Proposed, Litigation or Withdrawn), summary, impact, effectiveDate (or an explicit unknown), checkedAt, reviewedBy, verification=verified and sources with primary=true. reviewedBy must accurately identify automated review or an actual editor, never invent a human reviewer. The validator checks metadata and official domains, not the truth of a claim: fetch and compare the actual primary source before marking verified. Courts/official primary sources beyond the initial allowlist need a documented allowlist update. Recheck stays, withdrawals and expiry. Do not publish rumors. Copy no sensitive personal data or private chat content.

Use stable brand artwork and a separate dated editorial poster. Improve the generated SVG poster headline to summarize the edition's actual lead stories. Accompany relevant items with an accessible, lightweight image or a linked original media file when provenance and reuse rights are clear. Attribute official media and give text alternatives; never present an editorial illustration as documentary evidence. Do not download or rehost third-party media without rights. Every factual claim still needs its own source citation. Keep first-party lightweight assets and no trackers. Legacy pages retain their original media; new editions avoid automatic remote media loads.

Run node build.mjs, node --check dist/app.js, then browser-check archive filters, direct edition URLs, policy status filters, WhatsApp URLs, keyboard navigation and narrow screens. Confirm source citations and poster dates. Inspect generated pages without JavaScript too. Don't delete dist/archive dated files. Keep credentials in memory/stdin only.

Use Sites source helper to synchronize the exact source commit and package dist. Save and publicly deploy that version. Verify terminal success and URL before sharing the public edition URL. The live feed fetches first-party content.json every five minutes while a visitor has it open; changes require this publication workflow. This static app has no independent unattended writer. If publication fails, retain the edition and report failure; do not return an unverified URL as live.

Notify only on a published edition, meaningful failure or required action. No automatic WhatsApp messages: visitors choose to share. Do not create duplicate schedules. Keep pending cloud-schedule reconciliation visible until confirmed.

## Two-day visual digest archive

Maintain `content.json`'s `digestWindows` starting October 1–2, then October 3–4 and so on. The October 1–10 windows were prepared retrospectively on October 9 with partial source review; do not imply publication on those historical dates. On each future two-day edition, add its digest window after reviewing primary evidence and jurisdiction coverage. Keep the daily newsletter and full dated editions separate.

Each selected digest item needs a three-pillar category, source or event date, jurisdiction, affected people and U.S.-diaspora connection, policy status, effective date, uncertainty, exact source, checked date and honest reviewer. A later source that changes an earlier summary must be linked and dated. A missing item is not a no-update finding. List jurisdictions actually checked, checked without a qualifying verified update, and not individually checked separately; never imply a comprehensive 54-country and 50-state-plus-DC scan if it was not done. The generated lightweight SVG is editorial artwork, never evidence. Preserve old digest URLs when correcting a page.
